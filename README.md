# AI-Powered Invoice Data Extraction

A small Python command-line app that reads an invoice image, uses an AI model
(**Google Gemini**, via the Gemini API) to extract the key information, validates it,
and prints the result as structured JSON.

## What it extracts

- Invoice number and invoice date (plus due date)
- Supplier name (and customer name)
- Line items: description, quantity, unit, unit price, line total
- Subtotal, VAT, and total amount

## Setup

Requires Python 3.9+ and a free Gemini API key from https://aistudio.google.com/app/apikey.

```bash
# 1. (optional) create a virtual environment
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 2. install dependencies
pip install -r requirements.txt

# 3. add your API key
cp .env.example .env              # Windows: copy .env.example .env
# then edit .env and set GEMINI_API_KEY=your_key_here
```

## Run

```bash
python extract.py invoice.png                 # print JSON to the terminal
python extract.py invoice.png -o result.json  # also save it to a file
python extract.py path/to/other_invoice.jpg   # any PNG / JPG / WEBP / GIF
```

Optional: choose another model with `INVOICE_MODEL=...` in `.env` (default: `gemini-3.5-flash`).

Run the tests (no API key needed, the AI call is mocked):

```bash
python -m pytest -q
```

Check the validation logic without an API key or internet:

```bash
python extract.py --validate-json sample_extracted.json
```

## Example output

See [`sample_output.json`](sample_output.json). In short:

```json
{
  "source": "invoice.png",
  "data": {
    "invoice_number": "RT-2024-1052",
    "invoice_date": "2024-10-14",
    "supplier_name": "Rivertech Supplies Ltd.",
    "items": [
      {"description": "HDPE Pipe 110mm (6m length)", "quantity": 50, "unit": "pcs", "unit_price": 1250.0, "line_total": 62500.0}
    ],
    "subtotal": 100500.0,
    "vat_amount": 13065.0,
    "total_amount": 113565.0
  },
  "validation": {"is_valid": true, "errors": [], "warnings": []}
}
```

(`sample_output.json` was generated by running the validator on the values read
from the invoice; a live run should return the same data.)

Exit codes: `0` extracted and valid, `1` extracted but validation failed, `2` could not extract (bad file, missing key, API error).

## How it works

```
invoice.png --> extract.py --> Gemini (vision) --> structured data --> validation.py --> JSON
```

| File | Purpose |
|------|---------|
| `extract.py` | CLI, image loading, the AI call, error handling |
| `validation.py` | Consistency checks on the extracted data |
| `tests/` | Unit tests for validation and the full flow (mocked AI) |
| `sample_extracted.json` / `sample_output.json` | Example data and example result |

### Design decisions

- **Why Gemini?** It reads invoice images well, including table layouts, supports
  schema-constrained JSON output, and has a free tier, so anyone can run this project
  without paying.
- **Structured output via a schema.** Instead of asking for JSON in free text and
  parsing it (which breaks when the model adds commentary or markdown fences),
  the model is given a Pydantic schema and must answer in matching JSON. The
  response is then re-checked with Pydantic on our side.
- **Prompt rules.** The model is told to copy numbers exactly as printed, to
  *never calculate or guess*, and to use `null` for anything missing. Calculation
  is done by our own code, so a misread digit gets caught instead of hidden.
- **Decimal, not float.** Money checks use `Decimal` with a 0.01 tolerance.

### Validation checks

1. Required fields present: invoice number, invoice date, supplier name, total amount
2. Dates are valid `YYYY-MM-DD`, and the due date is not before the invoice date
3. At least one line item; each has a valid quantity and unit price
4. For each item: `quantity x unit price = line total`
5. Sum of line totals = subtotal
6. `VAT rate % x subtotal = VAT amount`
7. `subtotal + VAT = total amount`

Failures go into `validation.errors` (data contradicts itself); unusual-but-not-wrong
cases go into `validation.warnings`. The program reports problems instead of crashing.

### Error handling

| Situation | Behaviour |
|-----------|-----------|
| Image missing, empty, too large (>10 MB) or unsupported type | Clear error message, exit code 2 |
| API key missing or wrong | Clear error message with how to fix it |
| Rate limit / network problem / server error | Up to 3 attempts with backoff, then a clear error |
| Model returns empty / malformed output | Clear error message, no crash |
| Model cannot find a field | Field is `null`; validation reports it instead of crashing |
| Model misreads a number | Caught by the arithmetic checks, exit code 1 |

## Limitations and possible improvements

- One invoice image per run. Multi-page PDFs could be supported by converting each
  page to an image and merging the results.
- Batch mode (a folder of invoices) and CSV export would be easy additions.
- For higher assurance, flagged invoices could be sent to a human for review.
